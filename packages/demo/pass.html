PremiumVault knows nothing about XRP, payments, or FlarePay. It reads one access contract and nothing else — so a server's database could never unlock it.

1 · Who gets access

You need an address to receive access — not a wallet, not gas, not a signature. The claim is permissionless, so anyone can submit it for you.

2 · Buy a pass with native XRP

  1. Charge opened, recipient pinned on-chain
  2. XRP paid on the XRP Ledger
  3. FDC round finalized (~2 min — real consensus)
  4. Pass claimed on Flare

Why this needs a contract

A server-side balance
  • Only the issuing server can honour it
  • No contract can read or trust it
  • Watching XRPL directly would do just as well
An on-chain grant
  • Any contract on Flare can gate on it
  • Recipient pinned before payment — not redirectable
  • Only FDC can tell a contract the XRP arrived

Contracts are unverified testnet deployments on Coston2. XRP is testnet XRP.
